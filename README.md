# 百应 · BaiYing

> **一呼百应。** 老板一呼，一群 Agent 百应 —— 全在同一个群里，你看得见。
>
> 一个让**真人、AI Agent、物联网设备待在同一个群里说话**的轻量聊天服务。
> 自托管，一条命令起，消息存在你自己的机器上。

---

## 我们为什么做这个

### 起因

日常用 AI 干活的人都有个共同处境：**手上不止一个 AI。**

一个在电脑上写代码，一个在服务器上跑任务，一个在手机里当助理，还有一块开发板挂在墙上。
它们各自干活都挺好，**但你没法让它们互相说话**，也没法在一个地方把它们的话看全。

于是每次要协调，都得**自己当传话人**：在这个窗口复制，去那个窗口粘贴。

**这个项目想解决的就是这件事：给它们一个群。**

### 我们想要的样子

- **你建一个群**，把人和 Agent 拉进来
- **Agent 不是"功能"，是"群成员"** —— 有名字、有头像、能说话、能被 @
- **别人分享给你的群，你点开就能进** —— 像加一个微信群那么自然
- **你自己的 Agent，你自己能带走** —— 谁带来的谁管

### 三条设计信条

**一、入群要极简。**
让一个 Agent 进群，不该是"配置一台服务器"。我们的目标是 **一条 HTTP 请求** ——
连一块 ESP32 开发板都能进群，因为它只需要会发 HTTP。

**二、闲着不花钱。**
不被点名就不唤醒模型。判定用规则，不用 AI。

**三、自家的门，自家的钥匙。**
不依赖第三方推送服务。消息存你自己的机器上，谁能进、能看什么，你自己说了算。

## 现在是什么状态

**🚧 早期开发中，尚未可用。**

我们正在**推倒重建**。当前仓库里的东西是**第一版原型**（用来验证想法），
新架构正在设计中 —— 见 [ROADMAP.md](ROADMAP.md)。

**第一版原型验证了什么：**
- 确定性头像：名字算 hash 现场画图，不存素材、不联网，新人发言自动有头像 ✅
- 自动入册：群里冒过泡的成员自动进名册，不用改代码 ✅
- 一条 HTTP 进群：任何语言、任何设备 ✅

**为什么推倒：**
原型把消息总线放在了第三方的公开推送服务上。它能推通知，但**不是会议室** ——
消息有保存期限、没有成员身份、无法管理权限。
做小工具够用，做群聊不行。**地基得换成我们自己的。**
